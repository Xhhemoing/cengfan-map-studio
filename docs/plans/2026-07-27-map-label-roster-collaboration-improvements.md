# 地图标注、名单表达与协作改进计划

## 目标

把省份贴图、数据省份识别、名单表达和工程共享串成可验证的编辑闭环。现有项目与历史地标/装饰数据继续可读取，但不再提供无效的内置地标和装饰入口。

## 阶段一：省份贴图与地图可读性

### 任务 1：贴图透明度与比例输入

- `ProvinceAppearance` 增加归一化后的 `opacity`，默认 1，范围 0–1。
- 贴图 `<image>` 实时使用透明度，项目保存、撤销、模板与 SVG/PNG 导出自然继承。
- 比例依据只保留“省份占比”和“原图比例”；总体大小使用百分比数字输入，不使用滑块。
- 素材库和省份属性面板操作同一场景字段。

验收：旧工程默认不变；输入 65% 后 SVG 宽高变化；输入 40% 透明度后 SVG `opacity=0.4`。

### 任务 2：删除无效内置地标和装饰

- 内置素材列表不再暴露 `regional` / `decoration`。
- 素材库移除添加地标、添加装饰和对应上传类型。
- 历史工程中的已有实例与用户资源仍可迁移、显示和删除，避免破坏兼容性。

验收：新建工程无内置地标/装饰入口；旧工程载入不丢实例。

### 任务 3：标签定位与数据星标

- 省份名字优先投影 GeoJSON `properties.center`（行政中心），无效时回退几何质心。
- 所有数据中可解析到的省份形成统一集合；地图标签、省份选择器和素材库省份按钮显示 `*`。
- 星号只辅助寻找，不进入省份主键、筛选和保存字段。

验收：行政中心与几何质心明显不同的测试数据使用行政中心；有数据省份显示星号，无数据省份不显示。

## 阶段二：名单展示语言

### 任务 4：省份方框内按城市分节

- 保留省份、城市、院校三种顶层聚合。
- 省份卡增加“城市子分组”开关与稳定排序；同城市内继续按院校合并姓名。
- 扩展卡片高度估算和布局压力测试，保证多城市卡片不溢出。

### 任务 5：通用表达模板

- 场景增加可持久化的标题、分组标题和行模板，例如 `{province}`、`{city}`、`{university}`、`{names}`、`{count}`。
- 提供字段显隐、顺序和分隔符的结构化控件；高级模式允许直接编辑模板并即时校验。
- 模板错误回退到默认表达，不导致画布崩溃。

验收：用户能分别调整大学、姓名、城市的顺序、标签和分隔形式；项目恢复与导出一致。

## 阶段三：工程交换与实时协作

### 任务 6：完整工程包导入导出

- 新增完整工程 JSON 包，包含项目快照、素材、字体、版本与校验信息；与现有“仅资源包”并存。
- 导入前显示摘要并允许“替换当前工程”或“复制为新工程”；不自动执行不受信任内容。
- 增加 SVG/PNG 导出尺寸、倍率、背景透明和裁切范围设置。

### 任务 7：共享编辑房间

- 服务端提供房间创建/加入、快照获取和 WebSocket 操作广播。
- 操作以事务 ID、客户端 ID、基础版本和服务端序号传输；首版对同字段冲突采用服务端顺序 + 明确冲突提示，不静默覆盖。
- 支持重连补操作、成员状态、只读邀请、房主关闭房间；资源大对象按哈希上传，不在每次操作中重复广播。
- 持久化房间需要明确部署存储；本地开发可先使用内存房间并标注非持久。

验收：两个浏览器可加入同房间并实时看到数据、样式、移动与撤销结果；断线重连后状态一致；旧版本操作不会破坏较新快照。

## 风险与边界

- 实时协作不是前端按钮功能，必须先冻结事务协议和资源上传边界。
- 删除地标/装饰采用“停止新建、保留兼容”策略，避免历史项目数据丢失。
- 标签行政中心可能落在狭小省份边缘；阶段一先纠正数据源，必要时后续增加显式偏移表，且偏移必须有视觉回归依据。
- 当前工作树已有大量未提交修改；每个阶段只做目标文件补丁并在编辑前后核对 diff。

## 验证

每个阶段运行目标 Vitest；阶段检查点运行 `npm run test`、`npm run lint`、`npm run build`，并在桌面与窄屏真实浏览器中验证编辑、保存恢复和导出。
