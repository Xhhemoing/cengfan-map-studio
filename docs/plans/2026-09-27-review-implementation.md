# 9 月调研落实：项目实施计划

日期：2026-09-27。优先级入口：[ROADMAP](../ROADMAP.md)。
来源：《蹭饭图工作室：产品体验、智能化与架构演进报告》，2026-09-27，23 页；代码基线 `0b1d4e3c3c0d7276b7aafce47cb92056c137c178`。
交付 PR：[#53](https://github.com/Xhhemoing/cengfan-map-studio/pull/53)。实际验证：[QA 记录](../qa/2026-09-27-review-implementation.md)。本轮代码已实现，尚未合并或发布。

## 1. 交付目标与边界

目标是「名单可信、排版可控、交付可靠」，而不是扩大通用设计工具功能面。

- 保留「名单 → 地图 → 版式 → 内容 → 交付」、本地优先、现有 SVG/Worker、事务与撤销链路。
- 不修改 `ProjectDocument` v2 / 工程包格式，不恢复「一键智能排版」，不引入登录前置条件。
- 新增候选、问题与预览是派生状态；项目仍是唯一事实源。事实修改必须显式确认。
- 未导入到新表中的旧记录默认保留；不能以姓名唯一、隐藏、海外或缺失字段为由自动删除。
- 既有功能先查代码再排期；旧 QA 数字不冒充本次测试结果。并行顶栏 PR #52 保持独立。

## 2. 执行顺序、依赖与估算

下列工作量是单名熟悉仓库的开发者的初始工程估算，含编码、测试与评审修订，不含真实用户招募、外部字典维护或发布等待；不是完成日期承诺。每阶段按验收闸门决定是否进入下一阶段。

| 阶段 | 任务 | 前置条件 | 初始工作量 | 退出条件 |
|---|---|---|---|---|
| A0 | CF-01 基线与部署能力核验 | 无 | 1–2 人日 | 基线命令与代码能力可复核；生产配置单独验收 |
| A1 | CF-05a 导出冻结 + CF-06a 源工程提示 | A0 | 2–3 人日 | 等待期间编辑不混入输入，源工程不误作公开图 |
| B1 | CF-03a 差异导入纵向切片 | A0 | 3–5 人日 | 预览/人工匹配/一次提交/撤销形成闭环 |
| A2 | CF-02 问题入口 + CF-05b/06b 就绪与保存 | A1 | 4–7 人日 | 问题可定位，版本就绪可证，保存失败不报成功 |
| B2 | CF-03b 确认中心 + CF-04 局部修复 | B1、A2 | 5–8 人日 | 事实变更使确认失效，保护位置变化数为 0 |
| B3 | CF-07 任务化 AI | A2、B2 | 2–4 人日 | 仅生成允许提案，版本冲突阻止应用，本地流程独立 |
| C | 多规格、附页、模板容量、校区消歧 | A2、B2 | 8–12 人日 | 所有产物同快照，各自完成容量/隐私预检 |
| D | CF-08 在线确认与版本纪念册 | ≥5 位制作者验证、迁移设计评审 | 10–15 人日起 | 服务端记录隔离、可撤销凭据、可恢复持久化 |

本轮执行 A0 的代码/CI 核验以及 A1、B1 的可独立回滚切片。生产部署审计、完整 RenderPlan、公开投影、局部 solver、在线确认不属于已完成范围。下一批已落为 [#54](https://github.com/Xhhemoing/cengfan-map-studio/issues/54)、[#55](https://github.com/Xhhemoing/cengfan-map-studio/issues/55)、[#56](https://github.com/Xhhemoing/cengfan-map-studio/issues/56)。

任务责任按模块划分：导入与确认归名单/事务层；导出与保存归交付/存储层；局部修复归 solver/Worker；在线确认归服务端权限/RoomStore。未指定具体开发者；进入排期前由维护者认领，每个工作包单独评审与验收，不同时重写多个层。

## 3. 小型工作包

### CF-01：现状与质量基线（P0）

接入点：`.github/workflows/ci.yml`、`docs/qa/`、`docs/ROADMAP.md`、测试配置。

步骤：读取 main SHA 与已有 PR；核对 typecheck/lint/test/build、路由分包、导入 Worker、持久协作；串行运行当前基线；对失败记录「失败 → 原因 → 最小修复 → 同命令复核」。禁止取消断言或跳过测试来获得绿色。

验收：结论有代码或 CI 证据；CI 已存在的构建不重做；Windows 历史结果与本次 Linux 结果分别标注。全量失败未关闭时不声称可发布。本轮确认的是仓库接线与本地生产构建启动，不是线上反代、权限、存储的部署认证。

回滚：仅回滚对应测试/文档修订，不删除旧 QA。

### CF-02：可操作问题清单（P0，#54）

新增 `issue-adapter`，包装 `data-health`、`layout-health`、`resource-health`。模型包括稳定规则/对象标识、严重度、项目基准、原因、定位目标与可用动作。先接原阶段摘要，不加一级导航。

海外与有意隐藏是信息状态；缺必要事实、资源缺失、画布越界按当前输出用途判断。定位复用已有选中对象/名单行回调；修复调用事务或提案，不直接 set React 内部事实。

验收：同问题不重复列出；选择问题能定位；「已知且接受」与规则/事实版本绑定；源检测器的例外语义不丢失。撤销后问题重新计算。

回滚：撤下适配 UI，保留原体检器和工程数据。

### CF-03a：差异导入与保版更新（P1，本轮已实现）

接入点：`DataWorkspace` 候选审查、`import-diff`、`editor-student-actions`、现有 `ProjectTransaction`。新增纯函数匹配模块与独立预览组件；先抽取原组件职责，满足文件规模闸门。

操作：名单 → 展开导入 → 识别文本或导入 Excel/CSV → 审查候选 → 比较并更新 → 确认每项匹配 → 确认更新名单。可取消，可一次撤销。原追加/替换入口保留。

本轮候选不携带可靠源 ID，完整多字段唯一精确匹配只判定「未变化」，不能用姓名直接覆盖。疑似匹配明确选旧记录/作为新人/跳过。两个候选不得覆盖同一旧 ID。新表未出现记录一律保留。重复精确记录不得静默合并成一个人。带稳定源 ID 的修订表及解析器升级留给 CF-03b/#56，不能宣称本轮已经支持。

提交规则：保留旧 ID、可见性与无关字段；追加才分配新 ID；事实字段按原校验；空字段不作为清除指令。原人工省份默认保留，清除需显式勾选。只提交最终变更，一次可撤销；不触发全局布局刷新或重新生成全部 ID。预览绑定名单与候选指纹；确认事件及实际事务边界再次校验。无变化不生成历史；只读/过期不报成功。

验收：相同表重复导入、行序改变、同名不同人、30/60/100/200 人中改 3 人、新旧混合、目标 ID 冲突、旧记录缺席、海外、隐藏、无效行、取消/过期预览、重复提交；未改事实/ID/手工位置不变。城市/学校改变后仍应检查受影响分组，不承诺所有派生几何均不变。

回滚：移除比较入口与新模块，保留追加/替换；无文档迁移。

### CF-03b：本地确认中心（P1，#56）

先升级导出修订表、列映射和解析器，携带可追溯稳定 ID，保留旧表兼容性；回导仍先比较。按 `studentId + factFingerprint` 存核验辅助记录，不复制可独立编辑的姓名/院校/城市。先提供组织者确认和问题清单导出；任一事实字段变更使旧确认失效。

需要随工程转移的确认凭据必须设计正式存储/包版本，不能以本机隐藏数据库冒充可交接能力。匿名本人链接留给 CF-08。验收包括事实修改、撤销、重复回导、过期确认及跨设备恢复；撤下辅助入口可独立回滚，不影响原名单。

### CF-04：局部排版修复（P1，#56）

在原 solver/Worker 输入增加可移动集合、已有位置、固定障碍与移动代价；本次提案保护位置，不改 v2 永久锁定语义。优先移动问题对象，再显式扩大邻接范围。

顺序：完整内容/不出界 → 卡片重叠 → 连线/地理邻近/平衡。预览显示移动卡片数、最大位移、字号变化、剩余问题；不使用单一美观分数。失败保留原工程，不静默升级全局重排。

验收：同输入同算法结果一致，保护位置 0 变化，无法容纳时明确解释；确认后一次事务撤销；过期 Worker/提案不能落地。

回滚：撤下局部入口，保留原确定性布局和全局刷新确认。

### CF-05：固定版本交付（P0）

CF-05a 已实现：在异步等待前冻结当前已渲染 SVG 内容、尺寸、文件名与选项，不在字体等待后重新读取活动画布或最新项目名。沿用 Blob、generation 与 PNG/SVG 交叉导出语义；新 PNG 替代旧 PNG，但独立 SVG 不吞先发 PNG。字体等待 15 秒超时；PNG 上限 4000 万像素/单边 16384 px，超限给降低倍率或 SVG 提示。这是产品保护阈值，不是所有设备可成功分配内存的保证。

CF-05b（#55）：引入完整 `ExportJob`/独立渲染实例，冻结项目与资源清单，等待匹配版本的字体度量/布局 Worker/图片就绪，再序列化；状态显示固定版本。补解码/编码/跨域/容量不足的分类恢复路径。

重要边界：本轮冻结的是点击时已渲染帧，尚未建立完整 RenderPlan 就绪屏障。已有未完成的字体度量或布局结果是否对应当前事实，仍需 CF-05b 解决。

验收：字体延迟期间继续编辑、改名、改尺寸、切项目、多次 PNG 与交叉 SVG；内容与尺寸/文件名成套；失败不假报成功；不同产物实际下载。延迟竞态本轮有单元回归，实际下载有 Chromium 验收，不能混写成所有浏览器竞态验收。

回滚：回滚 hook 与快照模块，不改 SVG/PNG/工程包格式。PDF/X、CMYK、文字转曲另立项。

### CF-06：保存、备份与公开投影（P0）

CF-06a 已实现：工程包确认与交付栏说明「完整名单源工程」，隐藏记录/不显示姓名/不含资源包都不会移除包内名单。提示仅交给获授权制作者，公开传播前另行检查图片。下载成功说明是已交给浏览器，不确认磁盘写入成功。

CF-06b（#55）：复用 `editor-save-lifecycle` 加事务后的防抖检查点，分开此浏览器保存/工程备份/房间同步；显示最近成功时间、待保存、失败与恢复入口。不能在每次拖动同步序列化大资源包。本轮仅验收已有返回列表保存/刷新恢复，未改造自动保存。

CF-06c：独立 `publication-projector` 从白名单重建公开输出；检查隐藏记录、自由文本、SVG metadata/title/desc、素材和文件名。源工程不被改写，不把「不显示姓名」声称为匿名化。

验收：配额失败不报成功、恢复最后有效版本；公开产物不含禁用字段/源工程；源包保留完整数据并有明确提示。实际部署的权限评估单独记录，界面提示不代表自动合规。三段可独立回滚，公开投影不回写源工程。

### CF-07：任务化 AI（P1）

统一应用层 Proposal：基准、作用域、命令、来源、风险、事实改动标记、预期结果。复用工具白名单与事务；阶段任务卡提供问题解释/样式候选，不增加任意写 JSON/坐标旁路。

验收：非法 ID/资源/字段被拒绝；基准变化重新确认；样式任务不上传真实姓名；用户拒绝/服务失败仍能本地完成名单、布局、导出。回滚撤下新增任务卡，不删除原本地工具或数据。

### CF-08：记录级服务（P2，最后）

不复用可读全项目的 viewer。凭据绑定房间+记录+权限+过期时间，支持撤销；服务端只返回指定记录，修改仅形成待审核建议。持有链接不是实名验证。

扩展原 RoomStore 接口与 SSE/HTTP 协议，不先引入微服务/CRDT。按实测再决定 SQLite；超限/持久化降级可见。

验收：转发不能枚举全班、跨记录请求拒绝、过期/撤销生效、重启恢复、重复事务幂等、冲突可见。涉及确认/发布版本/校区持久事实时，工程包与协作迁移一同评审；迁移前准备备份、兼容读取及回滚演练，不以普通 revert 代替数据回滚。

## 4. 阶段 C 的具体拆分

| 子项 | 实现方式 | 验收 |
|---|---|---|
| 多规格成果 | 同一冻结快照串行任务，版本/用途文件名与清单；不建多画板 | 不同尺寸/隐私规格不串数据，不打包源工程到公开套装 |
| 密集区域附页 | 先独立地区名录图，与主图同过滤口径 | 不漏人、不重复计数，标题和组标识可追溯 |
| 模板容量 | 使用测量后面积、画幅、卡片数、最长文本筛选配方 | 不改名单，不默认缩到不可读，无 AI 也可选 |
| 校区消歧 | 本地别名/来源字典/已确认映射优先 | 无可靠来源保持待确认，海外同名不混国内 |
| 城市小卡/纪念版 | 经授权数据投影与命名快照 | 不增加住址/电话/实时定位，不覆盖历史事实 |

每个子项先独立原型和真实制作者验证，通过后才接入交付阶段；不得绕过 A2/B2 的正确性闸门。

## 5. 质量闸门

只用合成或获授权数据。覆盖 30/60/100/200 人，并逐步增加卡片数/长文本/素材尺寸变化。核心回归先写失败再实现；同时测试取消、错误、过期、撤销与多次操作，不仅测试成功路径。

仓库检查串行：`npm run typecheck` → `npm run lint` → `npm test` → `npm run build`。定向测试可单独运行；不并行跑多个全套重检查。保留文件规模闸门。

真实浏览器验收：新建 → 导入 → 比较更新 → 修改 → 撤销/重做 → 保存 → 刷新 → 导出 PNG/SVG → 重新打开工程。记录浏览器与视口；字体等待竞态和资源延迟单独记录测试层级，不把 jsdom 或单机成功推广到所有设备。

基线失败与新增失败分开。任何失败留下根因与复核，不靠重试取绿。未执行检查明确写「未执行」。PR 审阅/最终提交 CI/浏览器证据齐备后才声明对应切片可合入；部署另走 tag。

## 6. 产品验收与停止条件

招募至少 5 位真实制作者，用授权或等价脱敏数据分别完成新建、改 3 人、最终交付。先比较现状与问题/差量闭环，不同时换全部视觉风格。本轮尚未执行真实用户招募。

记录首张可接受预览时间、更新后的重确认/拖动数、无关对象变化数、导出失败/恢复率。关键固定用例目标：记录丢失、错误合并、越权披露、版本串台为 0；「60 人 5 分钟」只作待验证目标。

出现身份错配、源名单泄露、不可撤销覆盖或版本混用立即停止扩功能；先修可靠性。几何不可行是合法结果，不用删人/缩字/移动保护对象制造成功。

## 7. 分支、发布与回滚

所有 PR base 为 main；本轮 `feat/review-delivery-roster-20260927`，不修改并行顶栏分支。文档、名单切片、导出切片与验证修复分成可审阅提交。功能不需要数据库迁移；普通 revert 即可回滚，不重写 main 历史。不得自动上线或合并尚未验收的工作。
