# 反馈收集 SOP

目标：让开发者愿意提意见、让用户愿意说哪里用不了。关键不是入口多，而是 **提了一定有下文**。

---

## 1. 入口（只保留这些）

| 谁 | 入口 | 不要引导去 |
|----|------|------------|
| 班主任 / 班委 | 用户群、腾讯问卷、应用内「反馈」（若已做） | GitHub PR、开发者群 |
| 开发者 | GitHub Issue 模板、Discussions、开发者群 | 用户群里的 Excel 答疑 |
| 两边都可能 | `CONTRIBUTING.md` 顶部的分流表 | 邮件（尚未开通则不要写） |

问卷字段（腾讯问卷，链到用户群公告）：

1. 身份：班主任 / 班委 / 学生 / 开发者 / 其他
2. 场景：开学 / 毕业 / 校庆 / 同学会 / 自己部署
3. 卡在哪一步：安装 / 导入 / 布局 / 样式 / 导出 / 其他
4. 一句话建议
5. 是否愿意被联系（微信号选填）
6. 是否允许把建议写进公开 Changelog（昵称）

每周日把问卷新回复 **转录成 Issue**（标 `user-feedback`），不要只躺在问卷后台。

---

## 2. 标签与看板

Issue 标签：

- `user-feedback` / `dev-feedback`
- `bug` / `enhancement`
- `good first issue` / `help wanted`
- `needs-repro` / `wontfix` / `duplicate`

看板列：Inbox → 本周评估 → 做 / 不做（写原因）→ 已发布。

「不做」必须在 Issue 里写原因，否则没人再提第二次。

---

## 3. SLA

| 事件 | 时限 | 话术 |
|------|------|------|
| 新 Issue / 群建议 | 48 小时内第一条回复 | 「收到。我先确认是导入还是布局，今晚前回你。」 |
| 能否做 | 7 天 | 「这周做 / 放到毕业季前 / 不做，因为…」 |
| 已合并 | 发布后 24 小时 | 「已经进主分支，感谢 @xxx。用法：…」 |

同一人连续催：把状态更新在原帖，不要让他新开帖。

---

## 4. 每周五「意见变成了什么」

群公告 + GitHub Discussions 各发一次，结构固定：

```
本周收到意见：N 条
已改：…
明确不做：…（原因）
下周转：…
感谢：@昵称（可匿名）
```

这是开发者漏斗的主转化器。没有这篇，就不要抱怨没人提意见。

---

## 5. 从反馈到宣发

- 用户原话（脱敏）可以进小红书，需本人同意。
- 开发者槽点可以进掘金「我们改了什么」，点名 GitHub 用户名。
- 禁止把未脱敏名单截图用于宣发。

---

## 6. 征求意见置顶帖（创建 Discussions 或 Issue 后贴上）

```
标题：征求意见：导入、布局、导出（置顶）

我们最想听这五句（直接回编号即可）：
1. 你的第一份名单表头长什么样？识别错了哪些列？
2. 多少人开始觉得地图上卡片不可用？你希望怎么钻取？
3. 导出 PNG 时哪一步最不像「能拿去打印」？
4. 如果只能保留一个免安装功能，你选导入出图还是协作？
5. 你愿意贡献的是：文档 / 模板 / 测试 / 代码 / 只愿意骂？

用户请走问卷或用户群；开发者请用 Issue 模板。
48 小时内一定回。
```
