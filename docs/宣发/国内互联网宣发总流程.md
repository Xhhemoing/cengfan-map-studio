> **一句话**：先让人「不用安装就能看到效果、能提一句意见」，再谈 Star 和粉丝。  
> **制定**：2026-08-15 · **窗口**：2026 毕业季已过，进入淡季蓄水 + 开学季；下一主战场是 **2027 年 3–7 月**。  
> **对象**：班主任/班委/毕业生（使用）+ 前端/开源/独立开发者（提意见与贡献）。

配套可视化：在 Cursor 对话旁打开宣发总览 canvas（`china-promo-playbook.canvas.tsx`）。

## 0. 先看阻塞，再谈投放

现有小红书/B 站/抖音文案已经能发，但漏斗在「看到之后」断开。国内用户不会 `git clone && npm install`；国内开发者也不愿只对着 GitHub 空仓库猜怎么提意见。

| 优先级 | 阻塞 | 为什么卡住增长 | 完成标准 |
|--------|------|----------------|----------|
| P0 | 没有可分享的 HTTPS Demo | 小红书/微信几乎无法转化 | 域名 + HTTPS + 打开即可导入示例名单出图 |
| P0 | GitHub 在国内不稳定、无 Gitee 镜像 | 开发者打不开、班主任更打不开 | Gitee 公开镜像，README 双链 |
| P0 | 贡献入口残缺 | 想提意见的人不知道填什么 | `CONTRIBUTING.md` + Issue 模板 + 置顶「征求意见」 |
| P0 | 仓库 description / Topics 为空 | 搜索曝光为零 | description + topics 已填 |
| P1 | 用户群 / 开发者群未分开 | 班主任被技术讨论吓跑，开发者被使用问答淹没 | 两个群、两套公告、两个二维码 |
| P1 | 现网 8787 无 HTTPS、无备案域名 | 微信/QQ 直接拦截 IP 链接 | Caddy/Nginx + 备案域名（或临时用 Cloudflare Pages 静态预览） |
| P1 | 把 8 月当毕业高峰在发 | 错季节，内容违和、转化差 | 按本文日历改开学季 / 开源冷启动 |
| P2 | KPI 按「1 个月 500 Star」定 | 完不成会误判内容不行 | 改用本文现实 KPI |
| P2 | 对外文案出现「升学率」口径 | 与合规条款冲突，平台易限流 | 只讲去向分布与制作过程 |

**本周只做 P0，再大规模发内容。** 没有 Demo 和反馈入口的投放，等于给别人的截图引流。

现有服务器（`DEPLOY-SERVER.md`）：公网 IP `121.5.16.236:8787`，无 HTTPS、内存 1.9G、AI key 已耗尽。可以作内测，**不能当作对外主入口**。

## 1. 双漏斗（用户 × 开发者）

两条漏斗资产不同、话术不同、群不同，禁止混成「来 GitHub Star」。

### 1.1 用户漏斗（要的是「用起来」）

```
看见成品图（小红书/视频号/班群）
  → 30 秒内看到「能打开的效果」（Demo 或成品 + 示例包）
  → 3 分钟导入自己的名单（或先用脱敏 CSV）
  → 导出一张图发班级群
  → 进用户群 / 投案例 / 拉下一个班主任
```

转化口令（用户侧每条内容结尾只留一个）：

- 主 CTA：**打开 Demo 试一张**（或「评论区扣 1，发你试用包」）
- 副 CTA：**加用户群领示例 CSV**
- 不要把 GitHub clone 当用户主 CTA

### 1.2 开发者漏斗（要的是「提意见」）

```
看见技术故事（掘金/V2EX/即刻/开源中国）
  → 5 分钟跑起来（Gitee / GitHub + npm run dev）
  → 打开置顶 Issue「我们最想听的 5 个意见」
  → 留下一条真实槽点或 good first issue
  → 48 小时内被回复、被写进 Changelog
  → 成为模板/布局/导入方向的贡献者
```

转化口令（开发者侧每条内容结尾只留一个）：

- 主 CTA：**来这条 Issue 拍砖**（具体 URL，不要只说「欢迎 Star」）
- 副 CTA：**认领 good first issue** 或 **加开发者群**
- Star 是结果，不是请求

### 1.3 为什么开发者会愿意提意见

开源项目收不到意见，通常不是「曝光不够」，而是 **提了没有下文**。本项目用四条纪律换意见：

1. 每条 Issue / 群建议 **48 小时内** 有人回复（哪怕只是「已记录，本周评估」）。
2. 每周五发一篇 **本周你的意见变成了什么**（群公告 + GitHub Changelog）。
3. 文档、案例模板、脱敏数据、配图也算贡献，写进 `CONTRIBUTING.md`。
4. 意见被采纳后，下一条公开内容 **点名感谢**（昵称，不暴露学校）。

## 2. 国内渠道矩阵

精力按 **淡季 8 周** 分配：产品阻塞 25% · 开发者渠道 35% · 用户渠道 40%（开学季用户略高于开发者；若 Demo 仍未上线，把用户渠道降到 20%，先补阻塞）。

| 渠道 | 漏斗 | 优先级 | 内容形态 | 外链能力 | 淡季怎么用 |
|------|------|--------|----------|----------|------------|
| 小红书 | 用户 | P0 | 图文 + 1 分钟操作 | 差，GitHub 更差 | 开学季班级图、班委工具，评论扣 1 发 Demo |
| 视频号 / 朋友圈 | 用户 | P0 | 15–30s 成品 | 微信内可跳已备案域名 | 班主任工作号转发；私域主场 |
| 微信用户群 | 用户 | P0 | 示例包 + 答疑 | 群文件 | 转化沉淀，不在群里发技术 PR |
| B 站 | 双 | P1 | 5–8 分钟教程 | 简介可放链接 | 「Excel 到地图」教程，简介放 Demo + Gitee |
| 知乎 | 用户 | P1 | 回答已有问题 | 较好 | 搜「毕业墙」「班级去向图」去回答 |
| 抖音 | 用户 | P2 | 15s 快闪 | 几乎无 | 口播「搜蹭饭图」，淡季每周最多 2 条 |
| 公众号 | 用户 | P2 | 长文合集 | 菜单跳转 | 有 8 篇存货再开，不要空号 |
| 掘金 | 开发者 | P0 | 技术长文 + 沸点 | 好 | 架构/布局/导入，文末贴征求意见 Issue |
| V2EX | 开发者 | P0 | 求拍砖帖 | 好 | 节点 create/share，标题别写成软文 |
| Gitee | 开发者 | P0 | 镜像仓库 | 国内可访问 | 每周从 GitHub 同步 |
| 开源中国 | 开发者 | P1 | 项目登记 + 资讯 | 好 | 登记软件、发进度 |
| HelloGitHub | 开发者 | P1 | 月刊投稿 | 好 | 每月 28 日前投 |
| 即刻（独立开发者） | 开发者 | P1 | 短动态 | 中 | 周更进度 + 求一个槽点 |
| Linux.do | 开发者 | P2 | 开源分享 | 好 | 避免广告腔 |
| 思否 / 腾讯云社区 | 开发者 | P2 | 转载掘金 | SEO | 同一篇技术文分发 |

| GitHub | 开发者 | P0 | Issues / Discussions | 国内不稳 | 模板、Topics、征求意见置顶 |
| 阮一峰周刊 / 科技爱好者周刊 | 开发者 | P2 | 投稿 | 好 | Demo 可用后再投 |

KOL：淡季 **不做 Tier 1 付费**。先找 10 位真实班主任/班委当种子（Tier 3），用作品换模板，不要用「预计 +500 Star」许诺。

## 3. 平台转化细则（国内互联网真实限制）

| 平台 | 不要做 | 要做 |
|------|--------|------|
| 小红书 | 正文堆 GitHub URL；承诺升学率 | 封面即成品图；评论置顶「扣 1 发试用」；主页放微信号 |
| 抖音 | 指望简介外链 | 口播搜索词「蹭饭图」；置顶评论；同步视频号 |
| 微信 | 发 `http://IP:端口` | 备案域名或群文件发 `.cengfan` + 教程；视频号 |
| 知乎 | 发纯广告回答 | 先回答「怎么做毕业墙」，工具放在步骤 3 |
| V2EX | 标题带「神器」「3 分钟颠覆」 | 「做了个毕业去向地图编辑器，求导入/布局意见」 |
| 掘金 | 只写产品介绍 | 写一个技术点（避让布局 / 表头识别 / d3-geo） |
| B 站 | 无字幕的录屏 | 前 5 秒痛点画面；简介双链 Demo + Gitee |
| 即刻 | 连续发招募 | 一周一条进度，问一个具体问题 |

**统一短链文案**（有 Demo 域名后替换）：

```
试用：https://<备案域名>/
源码：https://gitee.com/<org>/cengfan-map-studio
意见：https://github.com/Xhhemoing/cengfan-map-studio/issues/new/choose
```

在不能放链接的平台，改口播/置顶：**「搜蹭饭图，或评论区扣 1」**。

## 5. 淡季 8 周执行计划（2026-08-18 起）

执行配置：1 名开发兼职 + 1 名运营兼职（可同一人）。每周日 20:00 复盘 30 分钟。

### Week 0–1 · 打开漏斗（阻塞周）

- [ ] 给现网加域名 + HTTPS（Caddy），或先上静态预览页（GitHub Pages / Cloudflare）展示成品与示例包
- [ ] 在 Gitee 建公开镜像，README 增加 Gitee 徽章
- [ ] `gh repo edit` 补 description 与 topics（见 §8）
- [ ] 开启 GitHub Discussions；置顶「征求意见：导入、布局、导出」
- [ ] 确认 Issue 模板可用（本仓库已提供 `.github/ISSUE_TEMPLATE/`）
- [ ] 建 **用户群** 与 **开发者群**，群公告用对应手册
- [ ] 修一条对外成品图的交付警告（水印安全边距、卡片遮挡），再截宣发图
- [ ] 小红书/视频号账号资料：简介不放 GitHub，放「毕业/班级去向地图」+ 微信号

### Week 2 · 开发者冷启动

- [ ] V2EX 发求拍砖帖（文案见 [投放文案-开发者社区.md](投放文案-开发者社区.md)）
- [ ] 掘金发 1 篇技术文 + 3 条沸点
- [ ] 开源中国登记项目
- [ ] 即刻独立开发者动态 1 条
- [ ] 标 5 个 `good first issue`（候选清单见 [good-first-issues.md](good-first-issues.md)）
- [ ] 48 小时内回复所有新 Issue

### Week 3 · 开学季用户侧

- [ ] 小红书 2 篇：开学季班级图 + 「班委 1 晚出图」
- [ ] 知乎回答 2 个已有问题
- [ ] B 站 1 条 6 分钟：导入 CSV → 导出 PNG（简介放 Demo）
- [ ] 视频号 2 条 20 秒成品快闪
- [ ] 用户群发示例 CSV + 开学 checklist

### Week 4 · 闭环

- [ ] 把 Week 2–3 收到的意见做成「本周 Changelog」
- [ ] HelloGitHub 投稿草稿
- [ ] 种子班主任 5 人私信（话术用 `docs/KOL/合作话术.md` Tier 3，去掉 Star 许诺）
- [ ] `npm run promo:check` + `npm run promo:report`

### Week 5–6 · 加码一条漏斗

若 Demo 已可分享：用户侧加到每周 3 条小红书 + 1 条视频号。  
若 Demo 仍不可分享：**停止加用户投放**，只维护开发者渠道与产品。

### Week 7–8 · 模板与 UGC 预热

- [ ] 征集「非毕业」场景：开学、校庆、同学会、社团
- [ ] 补案例模板：普高文科、职高（素材检查里的可选项）
- [ ] 公布 2027 毕业季时间线，开始收种子名单（脱敏）

## 6. 反馈闭环 SOP

详细模板见 [反馈收集SOP.md](反馈收集SOP.md)。压缩版：

1. **入口统一**：用户群表单 / 开发者 Issue 模板 / 应用内「反馈」最终都归到 GitHub Issue 看板。
2. **标签**：`user-feedback` `dev-feedback` `good first issue` `help wanted` `needs-design`。
3. **SLA**：问候 48h；能否做 7 天内给结论；做完 @ 原作者。
4. **公开**：每周五「本周意见 → 改动」；被采纳的意见可进 README 贡献者致谢。
5. **不要**：让班主任去看 PR；让开发者进用户群被问「Excel 怎么导入」。

## 7. 现实 KPI（取代「1 个月 500 Star」）

衡量 **试用** 和 **有回复的意见**，Star 只作参考。

| 指标 | 8 周（淡季） | 2027-03 预热前 | 2027-07 毕业季结束 |
|------|-------------|----------------|-------------------|
| 可分享 Demo 打开次数 / 周 | 有数据即可 | 200 | 1000 |
| 有效试用（导出过图） | 20 | 80 | 400 |
| 真实案例（脱敏） | 5 | 20 | 80 |
| 用户群人数 / 周活跃 | 40 / 30% | 150 / 25% | 500 / 20% |
| GitHub+Gitee Star 合计 | 40–80 | 150–300 | 500–1000 |
| Issue + Discussion（非自己开的） | 15 | 40 | 100 |
| 外部贡献者（含文档/模板） | 3 | 8 | 20 |
| 小红书粉丝 | 200–400 | 1000 | 3000 |
| 开发者文章（掘金/V2EX 等）阅读 | 3 篇累计 5k | 10 篇累计 20k | — |

复盘时若「阅读高、试用低」→ Demo/转化口令有问题；「试用高、意见少」→ 反馈入口有问题；「意见多、回复慢」→ 先停投放把 SLA 做上去。

## 9. 合规（对外必须遵守）

- 示例与截图：姓名打码，不去向+真名组合出现。
- 不宣称升学率、就业率、录取率；可说「按省份/城市看分布」。
- 不把真实名单上传到群文件或 Issue。
- KOL 内容需授权，见 `docs/KOL/内容授权协议.md`。
- 许可证为 AGPL-3.0-only：改过再做成网络服务须开放对应源码。收费政策见 `docs/开源与收费边界.md`（社区模板手续费、支付不进本仓；不做学校统付与印刷生意）。
