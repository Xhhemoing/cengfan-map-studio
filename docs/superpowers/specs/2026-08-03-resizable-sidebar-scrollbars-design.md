# 可调侧栏与细滚动条设计

## 目标

让编辑器的左右侧栏支持桌面端连续拖拽调整，同时将项目中的滚动条统一为更细、更克制的视觉样式，并保持窄屏抽屉行为与亮暗主题兼容。

## 已确认方案

- 桌面端（`min-width: 1121px`）显示左右两条可拖拽分隔线。
- 左侧栏宽度限制为 `180-360px`，右侧 Inspector 宽度限制为 `220-420px`。
- 中央画布保留至少 `480px` 的可用宽度，窗口变窄时自动收缩侧栏到可用范围。
- 拖拽后的宽度保存到 `localStorage`，刷新或再次打开后恢复；损坏或越界的数据回退到规范范围。
- 分隔线提供 `role=separator`、当前值、最小值、最大值和键盘方向键调整能力。
- 窄屏继续使用现有侧栏纵向布局和 Inspector 抽屉，不渲染桌面拖拽分隔线。
- 滚动条统一为 6px 轨道，轨道透明，thumb 使用现有边界色，悬停时提高对比度；Firefox 使用 `scrollbar-width: thin`，WebKit 使用伪元素，并覆盖亮色/暗色主题。

## 实现边界

- 新增 `src/lib/editor-layout.ts` 负责宽度常量、边界计算、规范化和持久化数据解析。
- 新增 `src/components/ResizablePanelDivider.tsx` 负责指针拖拽和键盘调整，不把布局状态写入项目历史。
- `src/App.tsx` 只负责布局状态、窗口变化响应和两个分隔线的组合。
- `src/styles.css` 负责 CSS 变量、桌面布局、拖拽态、滚动条和响应式/主题样式。
- 不修改海报数据模型、导出格式、撤销重做和移动端现有抽屉流程。

## 验收标准

1. 桌面端可分别拖动左、右分隔线，中央画布不会被挤到不可用宽度。
2. 侧栏宽度不会越过最小/最大边界，窗口缩放后仍保持有效布局。
3. 键盘方向键、Home、End 可调整获得焦点的分隔线，并正确更新 ARIA 数值。
4. 宽度刷新后可恢复，损坏的本地数据不会阻塞编辑器启动。
5. 侧栏、Inspector、数据表和横向工作流等滚动容器使用细滚动条，亮暗主题下均可辨识。
6. `src/lib/editor-layout.test.ts`、`src/components/ResizablePanelDivider.test.tsx` 和 `src/App.test.tsx` 的相关用例通过，类型检查和 Vite 构建通过。
