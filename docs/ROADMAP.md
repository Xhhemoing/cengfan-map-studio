### 自建部署的安全基线

面向自己架服务器的使用者。`HOST` 支持已在 0.1.2 落地，其余为文档与默认值工作。

| 项 | 说明 |
|---|---|
| ✅ `HOST` 可配 | 此前 `0.0.0.0` 硬编码在启动处，运维无法收口到回环 |
| 反代示例配置 | 提供 nginx / caddy 片段：`HOST=127.0.0.1` + 代理终止 TLS |
| 部署自检清单 | 上线前确认：端口未直接对公网、有 TLS、`WORKSPACE_API_TOKEN` 已设或明确 `AI_PUBLIC_ACCESS=1` |

## 0.2.0 — 左右栏信息架构

**规格已锁定，只排期不重设计。** 左栏答「进度 / 下一步 / AI」，右栏答「选中了什么、能改什么」。
任务顺序见 plans：P0 右栏减噪 → P1 左栏分栏（破坏性）→ P2 按搬迁表挪摘要 → P3 收尾。

不得触碰：`MapInspector` 默认展开测试锁；不恢复「一键智能排版」；`App.tsx` 不涨行数闸门；不改 `ProjectDocument`。

**开工前置**：
1. 跑一轮 [需求收集表](私域/需求收集表.md)，拿到 ≥5 条真实用户回复，用真实反馈覆盖推演优先级。
2. 每个 P 段结束做一次真实浏览器走查「工作台 → 导入 → 导出 PNG」，点击数不得增加。

## 明确不做

- 支付、套餐、付费解锁、模板手续费结算 —— 见[开源与收费边界](开源与收费边界.md)
- 恢复「一键智能排版」 —— 版式阶段用「刷新展示框位置」
- 整支合并大型历史分支（如 PR #11 的 62 提交）—— 只逐 hunk 摘取
- 为消除排版告警去改默认海报构图 —— 应改判定口径

## 发布纪律

1. 所有 PR 的 base 必须是 `main`。
2. 同时 open 的 PR 尽量不超过 2–3 个，超过先合再开。
3. 分支超过 7 天未合即关闭，需要的内容重新摘取。
4. 审计类任务产出 GitHub Issue，不要产出「只有文档的分支」。
5. 部署只从 tag 出，线上产物永远能对应到一个 commit。
6. 合并带 tag 的发布 PR 用 **merge commit**，不要 squash（否则 tag 会脱离主干历史）。
