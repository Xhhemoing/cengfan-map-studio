### R4-4 room-snapshot bench + 5 MiB persist cap — ACCEPT-WITH-NITS (fix forward; do NOT revert)
- The mechanism is correct and well-built. `jsonFitsWithinByteLimit` walks the record with running-budget early exit and per-string escape accounting that matches `JSON.stringify` byte-for-byte for the data that can appear here (checked: quote/backslash/short escapes +1, other C0 `\u00XX` +5, unpaired surrogates → 3-byte replacement in UTF-8 vs 6-byte escape +3, paired surrogates 0); `structuredClone` is now paid **only** for rooms that pass. Skipped rooms stay live, `skippedRoomCount` is persisted in the envelope, a warn fires per flush. The test proves skip + restart-mortality + warn-once. The claimed post-cap 0.02ms needs no bench run to believe: `jsonStringBytesWithin` first tests `value.length + 2 > remainingBytes`, so every bench payload (5/20/40 MiB strings vs a <5 MiB remaining budget) is rejected in O(1) before any scan.
- **The constant is wrong, and the verdict on the number is REJECT — calibrate in R5-1 (the code stays).** Three tiers now disagree: client import accepts 128 MB, room create/transaction bodies accept `min(8 MiB, 8 MiB)` (`DEFAULT_MAX_ROOM_TRANSACTION_BYTES`, index.ts:123), persistence keeps 5 MiB. Any room whose record lands in 5–8 MiB is accepted by the API, works live, and silently dies at restart — the server accepts what it refuses to persist, with visibility limited to a server console line no room member ever sees. R4-4's own bench says the latency budget allows more: 1×5 MiB = 14.79ms, 1×20 MiB = 68.92ms → ≈3.6ms/MiB, so ~12 MiB/room stays under a 50ms occupancy budget with margin — comfortably above the 8 MiB accept limit plus envelope/history overhead.
- Two more gaps for R5-1: the per-room cap does not bound **total** flush occupancy (100 rooms × ~15ms each is 1.5s; a snapshot-level budget with deterministic largest-first skipping is needed), and the 30s interval can queue a new snapshot onto `persistQueue` while a slow sink still holds the previous one — each queued op retains a full snapshot in memory (coalesce while in-flight).
- Why not revert: pre-R3-4, *all* rooms were restart-mortal; the cap narrows a one-round-old durability win while preventing a measured 507ms synchronous stall, and the skip is logged and envelope-recorded. Reverting reopens the stall; calibrating closes the band.
