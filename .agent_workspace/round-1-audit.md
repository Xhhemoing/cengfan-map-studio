## Architecture snapshot

Canonical state is `ProjectDocument` (`src/lib/project-document.ts`, snapshot + undo history). Everything else derives from it:

- **Editor composition** — `src/App.tsx` (2466 ln) wires workspace state, autosave (`LocalWorkspaceOverwrite` → localStorage draft + `browser-workspace-store` IndexedDB + `editor-project-store`), the collaboration send-effect (debounced 600ms `diffCollaborationDocument` → `submitRoomOperations`), and `usePosterExport`. `applyTransaction` in `project-document.ts` is the single write funnel; it currently runs `cloneSnapshot`+`normalizeScene` **three times per commit** (before-snapshot, transaction input clone, applied clone).
- **Render path** — `PosterCanvas.tsx` (1588 ln) projects province geometry (d3-geo), builds `occupiedPolygons` (full projected rings) and `layoutRequest`, whose cache key `createCardLayoutCacheKey` JSON-serializes **every polygon vertex** per request. Solve runs in `src/workers/card-layout.worker.ts` via `useCardLayoutWorker` with a 12-entry LRU (`card-layout-cache.ts`). Stale worker responses are rejected but stale solves still run to completion.
- **Layout solver** — `src/lib/card-layout.ts` (~1300 ln): quadrant/radial/right-stack/grid; the production path (occupied areas/polygons present, ≤80 cards) is `optimizedLayout` → `buildCandidates` (per-card rails) + pairwise connector scoring via `connector-geometry.ts` (`connectorGeometriesIntersect` is O(s²) with per-segment allocations). Fallbacks: `containFree` scans a 12px grid × all polygons; `repackAll` is worst-case O(n⁴). `scripts/perf-layout-bench.ts` measures **only the non-obstacle path** (baseline 400-card median 95.2ms, see `.agent_workspace/round-1-baseline.md`); the production `optimizedLayout` path is unmeasured.
- **Collaboration** — server room store `server/collaboration.ts` (versioned snapshots + op history, rebase via `collaborationOperationsOverlap`); HTTP/SSE routes in `server/index.ts` (one-shot events tickets, per-subscriber `JSON.stringify` broadcast, 20s heartbeat that `touch`es the room). Client: `collaboration-client.ts` (`subscribeRoom` = one-shot ticket + native `EventSource`), `useCollaborationRoom.ts` (rebase/backfill refs), and the App.tsx send-effect.
- **Import/export** — xlsx via SheetJS pinned tarball (`DataWorkspace.handleExcelFile` reads **first sheet only**, main thread); `binary-import.ts` header detection silently drops incomplete rows (`unparsed` always `[]` on the workbook path); text import in `import-data.ts`. Export: `export-poster.ts` serializes SVG → `encodeURIComponent` data-URL → `<img>` → canvas `toDataURL`, with a **fixed 4s timeout** regardless of poster size.
- **AI** — server agent loop (`server/ai/agent-loop.ts`, well-guarded budgets/receipts/rejection breakers) and client shadow-project session `src/lib/agent-session.ts`, whose landing transaction (`transactionForSteps`) **ignores per-step replay failures** when applying to the live document.
- **Persistence** — `project-store.ts` and `browser-workspace-store.ts` share one IndexedDB database (`cengfan-map-studio`, probe-then-upgrade dance); project store caches the connection forever with **no `versionchange` handler**.

Prior unmerged campaign `origin/cursor/sota-campaign-6231` (112 commits, +24k lines) already attacked resource-pack dedup, a11y, AI session rollback, export object-URL timing, SSE contiguity. Current main has **not** absorbed those; several defects it fixed still exist here in different code shapes.

## Highest-risk defects / complexity / races / I/O

Ranked by user impact × exploitability, with file:function evidence.

1. **SSE client permanently loses live sync after one transient disconnect** — `server/index.ts:753-763` deletes the events ticket on first GET; native `EventSource` retries the same URL, gets 403, and (per spec, non-200 → connection failed) never reconnects. `useCollaborationRoom.ts:206-217` only backfills on error; nothing re-mints a ticket or re-subscribes. Every collaboration session silently degrades to write-only after the first network blip.
2. **Client applies non-contiguous op events** — `useCollaborationRoom.receiveRoomUpdate` (131-139) applies `room.operations` whenever `room.version > versionRef.current`, even for `version = ref+2`, silently dropping the missing transaction. Also the App.tsx send-effect (App.tsx:584-591) sets `collaborationBaselineRef.current = applyCollaborationOperations(baseline, operations)` **after** an await, clobbering any baseline advanced by a concurrent remote event → divergence.
3. **Server crash chains in SSE writes and static serving** — `server/index.ts`: after `closed` lifecycle calls `response.end()` (777-780), later `members` events (e.g. `leave`, which does **not** check `room.closed`, `collaboration.ts:428-439`) call `response.write` on an ended response → `ERR_STREAM_WRITE_AFTER_END` error event with no listener → process crash. Heartbeat (803-806) has the same exposure and `touch`es the room forever. `serveStatic` (249-296) pipes `createReadStream` with no `error` handler (file removed mid-stream → crash) plus 3× sync `statSync` TOCTOU. Broadcast serializes the payload **per subscriber** (772-787): O(subscribers × snapshot bytes) on the event loop.
4. **Room-store authorization holes** — `collaboration.ts:leave` (428) and `refreshMember` (410) authorize only `"read"` and trust the body `clientId`: any **viewer** can kick every member from the roster or forge phantom members. `get()` (172-177) `touch`es rooms before any credential check, so unauthenticated probes extend room TTL. `findParticipant` (179-187) re-hashes the presented token once **per stored participant** per request; `subscribeLifecycle` (479-490) has no `maxSubscribers` cap.
5. **`applyTransaction` triple clone+normalize** — `project-document.ts:211-239`: every committed edit runs `cloneSnapshot` (which calls full `normalizeScene`, including province-styles rebuild) three times plus per-student object clones ×3. This sits under every drag-commit and inspector change; with 300+ students it dominates commit latency.
6. **`diffCollaborationDocument` quadratic stringify** — `collaboration-operations.ts:49-58,76-117`: `sameValue` JSON-stringifies both subtrees at **every recursion level** (O(depth×size) repeated serialization; base64 assets are inside the diffed `ProjectPackage`), and id-array diffing uses `left.find` per item (O(n²) over students). Runs on the 600ms collaboration debounce for every edit while in a room, and inside `rebaseRemoteCollaborationOperations` on every remote event.
7. **Layout solver production path unmeasured and superlinear** — `card-layout.ts`: `containFree` O(grid × (placed+polygons+vertices)); `repackAll` O(n⁴) worst; `optimizedLayout` O(orders×candidates×n²×s²) with `connectorGeometriesIntersect` allocating rect/corner/edge objects per segment pair (`connector-geometry.ts:197-239`); `orderResult` O(n²) `find`. `createCardLayoutCacheKey` (card-layout-cache.ts:28-48) re-serializes every province vertex on each layout request on the UI thread.
8. **IndexedDB lifecycle** — `project-store.ts:192-253`: cached `IDBDatabase` never installs `onversionchange` → other tab's upgrade blocks forever ("被其他标签页占用"); a closed connection permanently poisons the cached `ready` promise; `put`/`remove` miss `tx.onabort`; `migrateLegacyWorkspace` (154-190) has a read-then-write TOCTOU that can double-migrate across tabs.
9. **xlsx import silent data loss** — `DataWorkspace.tsx:273-298` reads only `SheetNames[0]`; `binary-import.ts:parseExcelWorkbookRows` (158-188) drops any row missing name/university/city with `unparsed: []` — the user is never told rows vanished. No GB18030 fallback for GBK CSV (campaign commit `cf746b6` fixed this; still applies). No import-generation guard → rapid successive file picks can publish the older file last.
10. **Export pipeline fragility** — `export-poster.ts`: fixed 4s `loadImage` timeout fails big posters spuriously; `encodeURIComponent` data-URL (~3× expansion of multi-MB SVG) + `canvas.toDataURL` base64 (~1.33×) instead of `toBlob`/object URLs; no error surface distinguishing taint/decode/timeout.
11. **AI landing silently partial-applies** — `agent-session.ts:transactionForSteps` (624-643): replay `execute()` results are discarded; a step that fails on the live document (e.g. student deleted since preview) is silently skipped while the rest apply — user confirmed N changes, got fewer, no signal. `truncateUtf8` (25-33) is O(n²) re-encoding, called inside a binary search in `compactAgentToolResult`.
12. **npm audit** — high: `nanoid@3.3.17` (< 3.3.18, GHSA-2v37-7h3g-55p8) via vite→postcss. Actionable with `npm update nanoid --package-lock-only --ignore-scripts`; must assert `xlsx` stays pinned to the SheetJS CDN tarball (package-lock.json:21, 5112-5115).
