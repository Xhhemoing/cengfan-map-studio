## Blocking finding: AI landing throws `DataCloneError` (T5 × T10 surface)

Evidence chain (failure → cause → fix → recheck):

1. **Failure.** `src/App.tsx:1513` wires `onCommit={commitProjectTransaction}`; `commitProjectTransaction` (App.tsx:632-644) calls `applyTransaction(current, transaction)`. For AI transactions, `applyTransaction` (project-document.ts:246) invokes `transaction.apply(cloneProjectForTransaction(project))`, and T5's `cloneProjectForTransaction` (project-document.ts:214-221) now sets `history: readonlyView(project.history)` — a `Proxy`.
2. **Cause.** Inside the AI transaction's `apply` (agent-session.ts:677-693), `new AgentSession(current, …)` runs `cloneProject(current)` (agent-session.ts:190-194), which calls `structuredClone(project)` on the *whole* document **including the proxied `history`**, and only strips history *after* cloning. `structuredClone` cannot clone a Proxy. Repro: `node -e` structured-cloning `{history: new Proxy(...)}` → `DataCloneError: #<Object> could not be cloned` (verified in this review). The `new AgentSession(current)` inside `apply` predates T10 (present at `897a2a6`), so T5's proxy is the breaking change; T10 kept the surface.
3. **Why no test caught it.** T10's tests call `transaction.apply(live)` directly with a real document (real history — structured-cloneable); T5's tests use hand-written transactions that never structured-clone their input. No test drives an AI transaction through `applyTransaction`. The AgentAssistant preview path (`AgentAssistant.tsx:370`, `apply(project)` on the raw doc) also works, masking the break until the commit click.
4. **Fix (recommended, one line + test).** In `agent-session.ts:cloneProject`, strip history *before* cloning: `structuredClone({ ...project, history: { past: [], future: [] } })`. Side benefit: stops structured-cloning up to 50 full history snapshots per AI apply/preview. Alternative (worse): unproxy `readonlyView` in project-document — loses T5's shared-history write protection. **Recheck:** add an integration test that lands `transactionForSteps` through `applyTransaction` (both success and rejected-replay paths), then re-run the targeted agent-session + project-document tests and the full suite.
