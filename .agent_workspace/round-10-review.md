### 2. Does the boot sweep actually run before the first reader? Any `.tmp` shape it would miss?

**Yes — proven structurally, not by clock.** In `createReadyAiServer` the awaited sweep (`index.ts:1091`) precedes the state-store `load()` (`:1094`), the room-snapshot load (`:1096`), and the snapshot-writer construction (`:1103`). That is the strongest available ordering proof short of instrumenting the event loop. The relocation of this pin out of `index.test.ts` (orchestrator commit `59e309f`) moved the test body verbatim; only file scaffolding was added.

**Shapes it would miss — three, all bounded:** (a) **A state file configured outside `dataDir`** via `AI_STATE_FILE` or `config.aiStateFile` (`index.ts:1092`) — its `.tmp` orphans live beside it and the sweep reads only `dataDir`. Real (the config knob exists in production), fix is small, filed **R11-2**. (b) Subdirectories of `dataDir` — `readdir` is non-recursive, but no writer creates subdirectories today, so this is theoretical. (c) A `.tmp` without a digits segment — no writer produces one; both atomic writers embed `process.pid`. Also worth stating: the sweep runs only in `createReadyAiServer`, not bare `createAiServer` — correct, since the production boot path (`isDirectRun`, `index.ts:1129`) goes through the ready variant, and an embedded/test `createAiServer` sweeping a caller's directory uninvited would be worse.
